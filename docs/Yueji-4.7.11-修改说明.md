# Yueji 4.7.11 / build 30

完整复制 YuejiV4.7.10，原版不动；包名 cn.yueji.balance、升级签名不变，APK不带测试账本。

## 本次功能

1. 账户余额更新记录的账户名称下方并排放置“转账 / 更新余额”。转账填写转出、转入、金额和时刻，双方同步生成余额与“账户1向账户2转账xx元”来源；独立保存，不写收入或支出，不发起真实付款。查看转账记录可编辑 / 删除，双方一起重建，已核对的真实余额保留。
2. 手动余额默认备注“用户手动更新余额”，支持修改 / 明确清空；同一时刻不同账户的备注互不覆盖。
3. 收入与大宗支出保存按钮上方统一增加“是/否计入账户收支”。新记录默认不勾选，账户可选；勾选时账户必选，收入增加、支出扣减推算余额并记录来源。不勾选只保存明细；收入仍参与统计和已覆盖余额区间的修正。大宗支出不再额外叠加到余额差月支出。
4. 补录使用距离最近的真实余额，排除自动推算记录作为锚点；同距取之前的余额。之前实测正推，之后实测逆推，保留原实测值。后续补充更近实测时可重算自动记录；核对为真实余额后不再被自动修改。同刻已有实测时保持该值并合并显示来源，不重复扣加；若交易发生在实测之后，请填写实际更晚时刻。
5. 资产趋势、收入 / 大宗支出和月支出关键位置增加简要提示。推算余额明确显示“非实测”，更新时间折线只能参考。

## 就近推算示例

10/21实测9000元、11/1实测5000元，补录10/30支出1500元：11/1距离更近。因为11/1真实余额已经反映10/30这笔消费，不能简单再从5000扣1500；应从11/1余额逆向还原10/30之后已知的资金变动。若中间没有其他已知流水，10/30交易后估算仍为5000元；若10/31已知到账500元，则10/30估算为4500元。未逐笔记录的其他消费依然未知，所以中间点不能当作精确实测。

## 月支出口径及边界

各账户上月末最后余额－本月最后余额＋覆盖区间内本月收入－报销垫付＋报销到账－投资转出＋投资回款－内部转出＋内部转入。

- 这里收入必须加回，不是从期初减期末中再扣。大宗支出已体现在余额减少中，不再额外加一次。
- 每账户独立取端点，包含本月首条记录与上月末记录之间的差额；中间推算波动不增加另一份支出。月初00:00记录作为两月边界，同刻自动资金流水还原为日历开端，避免交易串月或双计。
- 请尽量在每月最后一次收支后核对余额。缺少上月记录时仅计算本月已知区间，不把跨多月差额强行分配给一个月；某账户本月未更新会列出并标注部分，不补0，不给出完整日均。端点为自动推算时标注估算。
- 收入统计仍按本月记录；支出修正只计入余额区间覆盖到的收入。不同账户更新时间不同、缺少真实月末余额、未逐笔记录的消费都可能造成月份归属误差，软件不能凭空恢复这些信息。
- 原导入历史金额 / 截止衔接保留，推算记录不会移动导入截止。

## 数据兼容

JSON16读取1–16，保存转账、每账户余额备注 / 来源、nearestCash新口径。旧记录不自动更改是否关联账户；旧未修改流水保持原先的前推方式。SQLite仍为4，XLSX模板不变，转账及关联元数据的完整迁移必须用JSON。升级前备份，新格式不能交给旧版读取，不要卸载、清数据或直接降级。
