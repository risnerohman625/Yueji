# Yueji 4.7.4 / build 23

## 修复与变化

1. 按最新要求彻底移除 APK 内的截图识别：普通基金、自选、银行理财均不再提供截图入口，删除 ML Kit 依赖及 OCR 模型、示例截图、识别与截图清理生产代码。银行理财的收益改为手动添加每日日期/金额，支持负收益，并填写累计收益及可选本周收益。
2. 修复 `Row too big to fit into CursorWindow` 的可复现根因：4.7.3 把整个账本与基金历史放在 SQLite 一条 TEXT 行中。新数据库版本 4 以至多 64,000 个 UTF-16 字符分块，避免在代理对中间分割；整次保存使用 SQLite 事务。旧版本 3 的大行通过 SQL `substr` 分段读取，不删除用户记录。
3. 普通手动买入无需填写名称：根据代码查询并自动填名；已有持仓/自选身份可从本地复用。未查到身份且无缓存时不创建错误基金；有缓存而净值刷新失败时保留已知信息，未知净值不伪造。
4. 自选详情新增“购买”，名称与代码预填且不可编辑，只需填写金额、手续费、时间、资金账户等。该入口仅登记实际买入，不会向基金平台下单。更新净值及分红拆分资料不再重复调用名称查询。
5. 设置一级卡片整面使用主题浅色，二级使用更深主题底色，内容面板使用独立白色/深色表面，圆角裁剪一致；一级互斥展开，二级同父级互斥展开。收起/切换一级时一并收起旧子卡片。

## JSON 备份核查

- 4.7.3 的格式 11 编码已经包含 `watchFunds`、`watchGroups`、历史净值、收益率、资料、分组关系、周期和排序，并不是完全漏掉自选数据。
- 读取格式 1–11，未提供自选字段的旧备份按空自选处理。恢复是完整替换，**不是把旧备份与现账本合并**；确认框显示已购、自选和分组数量，明确提示旧备份没有的数据不会保留。
- 存在但类型错误的列表、重复基金代码、无效分组关联、非法净值日期等，在落盘前拒绝；校验失败保留当前账本。
- JSON 导入、导出和恢复写盘移至后台线程，并显示进度；JSON 文件上限 64MB，XLSX 仍为 10MB。新本地存储不改 JSON 对外格式。
- 恢复使用独立完整替换，不再沿用普通编辑的“合并较新行情”逻辑。恢复后使旧行情刷新、买入查询和表格导入任务失效，防止旧任务回写冲突。
- 没有取得用户实际故障数据库或旧备份，因此不能声称已验证每一份个人备份；已经用模拟数据重现截图中的同类 CursorWindow 异常并验证修复。

## 升级

- 工程完整复制至 `YuejiV4.7.4`，`YuejiV4.7.3` 保持原样。
- 包名保持 `cn.yueji.balance`，APK 沿用已有开发签名，以便覆盖升级。
- 不要先卸载、清数据。无法打开旧版时也优先直接覆盖安装新版。
- 数据库升级至版本 4 后不要直接安装更旧 APK；JSON 备份仍为格式 11。
- 交付 APK 不包含个人账本、测试账户、测试基金或私人截图。
