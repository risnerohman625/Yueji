# Yueji 4.7.12 / build 31

完整复制 YuejiV4.7.11，原版不动；包名 cn.yueji.balance、覆盖升级签名不变。发布APK不附带任何用户账本或测试数据。

## 主要变更

1. 账户历史分为真实余额和出入账金额卡片。勾选关联的收入、大宗支出、报销垫付 / 到账、基金与理财申赎、内部转账只显示正负金额和来源，不再生成就近 / 正向 / 逆向推算余额。入账绿色正数，出账红色负数；同一时刻不同来源可独立显示。
2. 账户卡片金额＝最后一条真实余额＋此后已关联的金额流水。之后录入新的真实余额就重新起算，之前的资金变化视为已含在该实测内，不重复扣加；同刻显式余额也视为已包含当时交易。旧隐式初始基准保留原期前含义。
3. 月支出端点只用真实余额：上月末最后真实余额－本月最后真实余额＋覆盖区间内本月收入－报销垫付＋报销到账－投资转出＋投资回款－内部转出＋内部转入。大宗支出已在余额差中，不额外加一次。报销到账不进入收入统计。没有本月真实余额时，不拿现金流水假装月末更新。
4. 金额卡片左滑编辑会进入对应原记录；删除仅隐藏当前账户这一张卡片，原交易和资金效果保留。若要撤销资金记账，编辑原记录取消关联或删除原记录。原收入 / 大宗支出 / 报销再次保存可恢复相应隐藏卡片，恢复幂等，不复制收入或多计资金。转账与基金买入显式重存也恢复对应展示。
5. 收入和大宗支出新记录仍默认不勾选，勾选后必选账户；报销垫付、到账提供资金流水选项，旧未关联状态不擅自改变。真实余额同账户同刻不允许重复，金额流水无此限制，真实余额与流水可以同刻并列。
6. 资产趋势按本地日期合并各账户真实更新，日末统一估值；当前日只取当前已知数据，不引用未来实测。同日不会创建多个时分点。继续保留每月最多4个记录日采样、十节点可滚动视窗；月 / 年模式取末个记录日。未逐笔记录的消费在后续实测前未知，因此曲线仅供参考。
7. 历史月编辑可固定已核准整月的截止，避免同月补录余额导致重复衔接。旧版未固定的历史保持旧衔接兼容，不擅自重写导入金额。

## 合成数据回归示例

- 9/30真实2000，10/10收入1000，10/20大宗支出200：账户暂显示2800；10/31真实2500后显示2500，月支出500，不是再叠加大宗后的700。
- 10/11真实6000，10/15基金买入2000：账户显示4000；10/20真实3000后显示3000，已知区间个人支出1000，基金划转剔除，基金资产单独计值。
- 垫付800后收到800分别显示负 / 正流水；垫付和返还都排除个人支出，返还不是工资收入。

## 数据与升级

- JSON17兼容读取1–17；旧cashGenerated缓存或cashAccounts所有权单元格迁移时清除，真实余额、原收支、报销到账和投资记录保留，不删除其他账户单元格。
- 新增稳定Receipt.id、账户hiddenActivityKeys、历史fixedCutoff；来源键不使用时间，同刻不同交易独立。旧时间删除标记不再屏蔽新版金额卡片。nearestCash只保留旧区间兼容字段，不再触发任何余额推算。
- SQLite仍为4、XLSX表头不变；关联身份、隐藏状态、整月固定、转账及完整投资资料请用JSON完整备份。恢复是替换，不是合并；升级前备份，不要向旧版导入格式17，不要卸载清数据。
- 私人调试数据、修正版账本、逐项审计与截图仅在本地隔离位置保存，不进入公开仓库、APK或发行附件。未知出款账户、未知银行凭证和缺失月末余额不能凭金额接近猜测；待核准项单独交付私人说明。
