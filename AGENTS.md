# Project version policy

The user requires a separate full backup copy for every version, named
`<software name>V<major>.<minor>.<patch>` (for example `YuejiV4.1.0`).

- This is `Yueji V4.7.0` (versionName 4.7.0, versionCode 18), fully copied from `YuejiV4.6.6`, which remains untouched.
- Earlier versions are kept untouched in sibling folders (`SemordnilapV1.0.0` ... `SemordnilapV4.0.0`).
- For the next version, copy this folder to the next `Yueji Vx.y.z` folder before editing. Never overwrite existing versions.
- The package name stays `cn.yueji.balance` so installs upgrade in place.
- The delivered app must be blank: no bundled accounts, income, expenses or funds. Test data goes through the test suites only. Do not clear installed app data.
- Import/export is .xlsx (Xlsx.java, HistoryImport.java, FundSheet.java); formats and the month bridge rule are in `docs/Yueji-导入导出说明.md` and `docs/Yueji-功能总结与开发注意事项.md`. Keep them in step with any change.
- Only .xlsx data import is supported: exact sheet names and complete ordered headers, no CSV/text fallback, no code zero-padding. JSON remains the independent full-backup format.
- UI parts live in Ui.java / Segmented.java / NavBar.java / SwipeRow.java; reuse them. Use Ui.fit for bounded values; do not combine setSingleLine(true) with auto-size text.
- Android Studio and SDK live in `D:\ProgramData\Android`. Build with `tools\build.ps1 -Check`, JVM tests with `tools\test-ledger.ps1`, and `tools\build-androidtest.ps1` to build the instrumentation APK (run on the emulator with `adb shell am instrument -w cn.yueji.balance.test/androidx.test.runner.AndroidJUnitRunner`).
- Line-chart selections hide 2500 ms after release; annual bars have only an above-bar tooltip. Axis labels use compact Chinese 千/万 units; stored monetary values remain cents.
- `MonthLedger` calculates monthly expenses from each account's own consecutive observations after the historical cutoff. Single observations are real zero-expense baselines. Missing months are drawn as zero only on the chart, with a separate known-data mask so they cannot become extrema or fake ledger records.
- `YearStepper` opens an anchored three-row NumberPicker with faded edges, exactly as wide as its button. The native wheel supports light scrolling and accessibility actions. `FlowLayout` handles draggable flow entry cards.
- Network operations use `NetworkIo` to bound a complete fetch to 18 seconds. Foreground failures use one short modal, never raw exception strings on fund cards. A failed fetch must retain cached NAVs and ledger records.
- Snapshot.partial marks genuine per-account observations; never fill other accounts with zero or copy stale balances as new observations. Existing full snapshots still require all then-active accounts.
- JSON format 9 adds refreshMinutes; read formats 1-9. Format 8 debt/repayment and lossOnly stay intact. Format 7 import ownership and revision tombstones remain intact. Preserve deleted revisions internally so a later rollback cannot resurrect a deleted batch. Never infer legacy import origins. Old versions must reject new backups rather than silently lose fields.
- Fund screenshot import accepts completed purchase-detail pages, not the multi-fund transaction list. Match the entire recognized fund name character-for-character; no punctuation/case/share-class normalization for automatic matches. Uncertain identities require online code verification and explicit correction.
- Group same-line OCR fragments geometrically. Normalize label variants only; never normalize product identity. A valid but incomplete detail page goes to editable review, not a wrong-image error. Missing fees stay blank in the editor; missing purchase times require explicit user acknowledgment. Name lookup failure is not a screenshot-format failure.
- `ImportJournal` records only committed additions/replacements; duplicate skipped rows are not owned. Entry and buy ownership follow immutable IDs, including edited/moved buys. Month and bank rollback must protect newer revisions/manual modifications and never erase unrelated transfers. The UI has one expanded batch; old/manual records remain explicitly unattributed.
- `FundNameView` fits the full name in one line at 15-11sp; if still too long, restore 15sp and scroll horizontally. Only the title captures this gesture; the remaining card retains swipe actions. Display holding percentage in the footer, not beside the name; no fund code on home cards.
- Multi-image import supports at most 20 images. A same-code/same-minute existing buy is shown as already added and deselected. Gross amount, fee and purchase time come from labeled fields; never use paid amount, confirmation date, NAV, shares or order number as substitutes.
- `ScreenshotCleanup` deletes only successfully committed selected source images when the default-checked checkbox remains enabled. Honor system/provider deletion consent and report failures. Never delete cancelled, failed, unselected or unrelated sources.
- Bank import is manual/upload only: no MYbank launching, screen capture service, overlay or media-projection permissions. Opening form has name, amount and corresponding time; screenshot entry fills name/amount only.
- Bank day/week/month/year calendars use actual imported evidence; no weekly averages. Missing dates stay pending. Total day/yesterday portfolio returns exclude manually updated banks, while value, held profit and return rate include them.
- `BankAccounting` fixes principal from the opening amount and corresponding cumulative evidence once. Reimports replace same-date evidence without repeatedly subtracting profit. Completed BUY/SELL events use completion time, historical pre-anchor flows are not double-counted.
- Preserve old product segments and CHANGE events; prevent importing old-product days into a new segment. Missing/unreconciled transition evidence stays unknown. Do not fabricate NAVs, daily returns or bank product codes.

- Debts are independent cash-basis memo records; never insert synthetic income, expense or balance observations for loans/repayments. Validate no overpayment, preserve every dated repayment, dim and sort paid loans last. JSON format 8 must retain all debts.
- AppIcons owns the three launcher aliases, app dialogs/toasts, recent-task artwork and notification content/small icons. Keep exactly one enabled launcher alias; never claim ordinary apps can mutate the system's fixed ApplicationInfo icon dynamically.
- The year wheel hides original text, never closes while touched/flinging, and dismisses 1000ms after idle. Cancel pending callbacks on detachment.
- Fund background refresh uses persisted JobScheduler every ~2h with networking, not a foreground service. No exact-time or force-stop bypass promises. Default alerts only confirmed losses; system owns heads-up policy.

- Version 4.6.4 only adds native-library APK deflation (jniLibs.useLegacyPackaging=true); all four ABIs and original ML Kit payload bytes must remain unchanged. Run tools/compare-apk-payloads.py against the frozen 4.6.3 APK. Do not switch to a downloadable/remote OCR model or drop ABI support to simulate compression.
- The explicit user rule is that debt is record/display only: loans and repayments must never affect total assets, bank/account balances, income or expenses automatically.

- Current overrides (4.6.5): App name is Yueji everywhere. Three purple icons in one row; selecting only writes pendingIcon, with no launcher switch or process exit until next full activity/process start. Imported custom images are cropped locally and support an explicit pinned shortcut; never claim arbitrary uploads can rewrite manifest launcher icons.
- Native notifications contain only message text and small icon; do not duplicate app artwork/name/time in RemoteViews. Automatic refresh/notifications and first fund-page entry obey Shanghai 09:30-11:30 and 13:00-15:00 sessions on trading days, excluding lunch/holidays/weekends. Manual user refresh/import remains unrestricted. Interval is user-configurable, not an exact system execution guarantee.
- FundRules sort mode 2 means absolute holding profit, not rate. PortfolioOrder sorts the combined fund/bank list with stable ties. PortfolioSummary applies the active category to all header totals and the curve; bank-only uses this/last week, all-products includes only explicit same-date bank returns and contributes zero for missing bank days. Do not change the stored calendar evidence to synthetic zero.
- StorageScreen may clean only cache directories, never models, database, imported records or valid NAV history. Installed app size includes extracted native libraries and platform optimization. Test QA screenshots contribute to emulator external data and are not shipped in the app.

- Current overrides (4.6.6): replace uploaded icon/crop/shortcut UI with one three-built-in-icon dialog. Selection stages pendingIcon; apply on next full activity/process start. Legacy custom selection migrates to two petals without deleting the original imported file. The fixed manifest application/round icon and default launcher/small icon are two petals. Three launcher aliases and app-controlled dialog/task/notification icons follow the applied choice. System-owned app-management/package artwork cannot be dynamically replaced through activity aliases; never promise this on every OEM surface.
- Asset page defaults to account list; left/right selectors cycle composition, trend, accounts in place. Account actions stay outside the replaceable panel. AssetSlices may enlarge only visual angles (minimum 3 degrees for ordinary positive slices); labels and selected values use true percentages. Real zero amounts have no synthetic slice. Selection hides leaders until 2500ms after release.
- AssetHistory reconstructs each account from its own latest actual observation/opening balance at the requested time, respecting creation/deletion. It never saves synthetic snapshots. Include historically known fund valuations and actual bank statement segments/completed flows; missing NAV/transition evidence creates gaps, never latest-NAV backfill or synthetic zero. Debt remains excluded. Monthly/yearly mode takes the last real observation in that period, with no empty-period fabrication. Date mode selects up to four real observations per month approximately evenly by elapsed time. Extrema use consecutive unsampled observations, not sample-to-sample differences.
- AssetTrendChart fixes a ten-node viewport for longer series. Only the separate horizontal axis scrolls the series; dragging the plot selects its cursor and never pans. Cursor expires 2500ms after release. All financial y axes share ChartScale.label with 千/万 compact values; this explicit user override replaces earlier unit-free rules.
- FlowOrder now has four IDs (income, large expense, reimbursement, debt). Migrate existing three-card order by appending debt; keep all four in the same draggable FlowLayout. Never alter ledger data when sorting.

- Additional explicit user rule (4.6.6): new in-app INCOME and REIMBURSE entries must select an account. Income credits it; advances debit it; each new receipt must select its own account and credits it. All three create post-transaction balance observations through AccountCash. This explicit authorization supersedes the earlier prohibition on synthetic snapshots for these cash events only; do not fabricate untouched account cells, market values, loans or repayments.
- AccountCash owns only cashGenerated snapshots and cashAccounts cells. Rebuild owned cells on save after additions/edits/deletions, preserving every absolute manual observation. A same-time manual account balance is post-transaction and wins without adding the flow twice. A later absolute observation resets the running balance; editing older cash records must not shift it. User can verify a generated cell as manual, removing that cell's automatic ownership.
- Linked post-transaction cash corrections use (firstObservation,lastObservation]; legacy entries keep their previous [start,end) convention and never silently acquire cashLinked. Legacy imported income/advances/receipts stay unchanged, including unassigned accounts. New receipt on an old reimbursement applies only that receipt's credit. Reject missing accounts, pre-opening dates, deleted-at-time accounts, and negative/overflow balance. The editor preserves income time so generated balances do not silently move to midnight.
- JSON format 10 stores Entry.cashLinked, Receipt.cashLinked, Snapshot.cashGenerated/cashAccounts. Read 1-10, old flags default false. Keep xlsx sheets/headers unchanged: importing history remains observational and does not auto-credit old transactions; complete roundtrip of ownership requires JSON. Generated cash observations must not move imported history cutoffs.

- Current 4.7.0 overrides: JSON format 11 reads 1-11; fund and completed bank investment cash flows may link accounts. Historical unlinked trades never auto-debit. Recurring plans record actual confirmed user purchases, never execute financial orders. Watchlists use separate market records, immutable buy IDs for recurring history, total-return analytics and calendar years plus remaining days for fund age. Detail metric rows use equal-width centered columns. Public GitHub excludes private fixtures, historical workbooks and older APKs.
